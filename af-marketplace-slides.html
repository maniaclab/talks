What is it?

A Claude Code plugin built for ATLAS facilities

The marketplace packages facility-specific knowledge and AI skills so Claude understands your infrastructure — HTCondor, Rucio, ServiceX, Coffea — right out of the box.

🧠
Facility-aware AI
Claude knows the UChicago AF stack: queues, storage paths, container images, and common workflows.

Plugin system

Installation

Two ways to install

Option A — from GitHub (recommended)
CLAUDE CODE # In any Claude Code session /plugins marketplace add     usatlas/marketplace   # Then install the plugin from # the marketplace interface # → select "analysis-facilities"
💡 This pulls directly from the usatlas GitHub org — always gets the latest skill updates.
Option B — local clone
BASH + CLAUDE CODE # Clone the repo first git clone   https://github.com/usatlas/marketplace   # Then point Claude Code at it /plugins marketplace add     /path/to/marketplace
⚠️ Local installs don't auto-update. Use GitHub install unless you're developing the plugin itself.

Login Server

Connecting via SSH

The login nodes are your command-line gateway to the entire facility stack.

Quick connect
TERMINAL ssh login.af.uchicago.edu
SSH config shortcut (add to ~/.ssh/config)
~/.SSH/CONFIG Host uchicago   HostName login.af.uchicago.edu   User <your-username>   ForwardAgent yes   IdentityFile ~/.ssh/id_ed25519   # Then just: ssh uchicago
🔑
SSH key required
Upload your public key during account signup. Allow ~15 minutes for sync before first login.
⚙️
What's on the login node
CVMFS, condor_submit, Rucio CLI, HTCondor tools, your $HOME and $DATA directories.
🤖
Running Claude Code here
Open a terminal, run claude — the marketplace skill auto-loads when you mention the AF.

Storage

Storage layout

Understanding where to put your files — inputs, outputs, code — saves time and avoids quota issues.

$HOME — /home/<username>
25 GB
Backed-up personal space. Store code, configs, small reference files. Not for large datasets.
$DATA — /data/<username>
1 TB+
High-capacity scratch. Use for analysis data, ntuples, job output. Purged periodically — keep only active data.
CVMFS — /cvmfs/atlas.cern.ch
Read-only
Distributed software repository. ATLAS releases, Rucio, and analysis software live here. Fast, cached globally.
XCache / Rucio — remote datasets
Petabytes
Access ATLAS grid data via Rucio or XRootD. Use rucio get or direct XRootD URLs in your jobs.
HTCondor

Submitting HTCondor jobs

Submit batch jobs directly from the login server. Claude Code can write, submit, and monitor condor jobs for you.

Minimal submit file
MY_JOB.SUB executable = run_analysis.sh arguments = $(ProcId) output = logs/job.$(ProcId).out error = logs/job.$(ProcId).err log = logs/job.log   request_cpus = 1 request_memory = 4GB request_disk = 5GB   queue 10
Common commands
🚀
Submit
condor_submit my_job.sub
🔍
Monitor
condor_q — watch your jobs; condor_watch_q for live view
📊
Job history
condor_history shows completed jobs and exit codes
💡 Ask Claude: "submit 100 analysis jobs using my run_coffea.py script" — it will write the submit file and run condor_submit for you.
Data Access

Rucio & XRootD on the AF

Access ATLAS grid data without leaving your analysis environment. Rucio and XRootD are pre-configured on all AF nodes.

Rucio CLI essentials
TERMINAL # Set up environment source /cvmfs/atlas.cern.ch/repo/ATLASLocalRootBase/user/atlasLocalSetup.sh lsetup rucio   # List dataset contents rucio ls user.myname:mycontainer   # Download dataset to $DATA rucio get --dir $DATA user.myname:mydataset
XRootD streaming
PYTHON import uproot   # Open file directly via XRootD f = uproot.open(   "root://xcache.af.uchicago.edu//   path/to/your.root" )
💡 XCache at UChicago caches remote ROOT files locally — subsequent reads are much faster.
Analysis Frameworks

Coffea & ServiceX workflows

The UChicago AF is optimized for columnar analysis with Coffea and ServiceX — the marketplace skill knows both APIs.

☕
Coffea
Columnar analysis framework built on Awkward Array and Dask. Pre-installed in the coffea container image on the AF. Run locally or scale to HTCondor workers with coffea-casa.
coffea-casa Dask Awkward Array
📉
ServiceX
On-demand data delivery service. Request filtered/transformed columns directly from grid storage. Returns Awkward Arrays or Pandas DataFrames. Reduces I/O drastically.
func_adl TTree Arrow
💡 Claude Code with the marketplace skill can scaffold a full Coffea processor, submit it to ServiceX, and run it on HTCondor — just describe your analysis in plain English.

Container Images

Available container images

Pick the right image when spawning your JupyterLab server. All images include CVMFS, Rucio, and HTCondor client tools.

🛠 ATLAS Analysis
atlas/analysisbase
Full ATLAS software stack via CVMFS. Use for standard ATLAS analysis, AOD processing, and derivation jobs. Best for established workflows.
☕ Coffea / columnar
coffea-casa
Coffea, Dask, Awkward Array, uproot, hist, mplhep pre-installed. Best for columnar analysis, post-processing ntuples, ML pipelines.
🤖 ML / GPU
ml-platform
PyTorch, TensorFlow, CUDA drivers, GPU-optimized libraries. Select a GPU profile when spawning. Up to 3 A100 GPUs available.
🔌 Custom / BYO
custom image URL
Provide any Docker/Singularity image URL. Must be accessible from the AF nodes. Contact support for private registry access.
